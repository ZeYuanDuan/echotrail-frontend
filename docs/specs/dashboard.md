# Dashboard 已保存快照

使用者按「確認 Echo Card」後，前端先保存事件，再自動重算 Dashboard。後端依該 `userId` 讀取**全部**已確認事件洞見和訊號，產生整體 Persona、共鳴之錨、關鍵字、行為模式、北極星與框架訊號預覽，原子保存為一筆 `dashboard_runs`。只有事件保存成功才會開始重算；重算失敗或來源版本衝突時，事件仍保留，前一個成功快照仍可讀，使用者可從確認畫面或 My Trail 重試。

前端 Dashboard 頁只呼叫 `GET /api/dashboard?userId=<uuid>`。回傳 `null` 時顯示空狀態；載入失敗顯示重試。Persona、文字、框架分數與證據均取自同一個 `DashboardSnapshot`，不從瀏覽器事件資料推算。重新載入會再次 GET；切換暱稱會先清空舊快照。

Dashboard 不提供獨立的「分析框架」頁；舊網址 `/dashboard/frameworks` 會回到 Dashboard 總覽。前端只呈現職場北極星需要的 Schein 多維訊號，不顯示 RIASEC、DISC、框架切換、長條圖或 DISC 象限。

Dashboard 的 Persona、共鳴之錨、重複關鍵字、行為模式與職場北極星五個子頁，內容主標題必須維持在頁面 H1 之下的文字層級。桌面版子頁標題為 22px，手機版為 20px。
「我的共鳴之錨」子頁與 Dashboard 總覽共用同一個三圓交集圖，顯示能力、動機、價值及核心職涯錨定。子頁圖表只保留三個分類標題，避免長文字被中央錨定遮住；圖表下方另以三個區塊完整列出能力、動機與價值。手機版三圓圖依容器等比例縮放，避免固定尺寸造成上方圓形過度重疊，核心職涯錨定卡片則移到三圓圖下方，不覆蓋黃色圓形。
「重複關鍵字排行榜」依權重呈現字級，但桌面與手機版都有最大字級。關鍵字可以換行，資料增加時區塊應自然向下延伸，不得水平溢出、截斷資訊或撐破 Dashboard 版面。
Dashboard 總覽的職場北極星卡片以卡片標題為最高文字層級，主要錨定為輔助標籤，洞察標語與說明不得放大成巨型標題。洞察標語桌面版為 18px，手機版為 17px，說明正文為 14px。

`frameworks.scores.schein` 包含八個固定在 0～100 的職涯錨點指數。產生 Echo Card 時，LLM 逐一檢視八個維度，只為有逐字證據的維度產生 -10～10 的非零整數；正數表示支持，負數表示明確不重視、排斥或衝突，沒有方向性證據時省略。單一事件可同時影響多個錨點，但同一維度在同事件中最多一筆。

每個維度以 50 為沒有方向性證據時的中性基準，使用 `round(50 + 50 × 淨分數 ÷ (20 + 絕對分數總和))` 聚合所有事件，最後再限制於 0～100。20 點先驗權重避免少量事件產生過度極端的輪廓；正負證據增加時，指數才逐步遠離 50。前端也會重新限制回傳值到 0～100，避免舊快照或異常資料超出雷達圖。

框架結果包含計分版本。讀取未帶目前版本的舊 Dashboard 快照時，後端會直接使用快照內已保存的逐筆證據換算新版指數再回傳，不呼叫 LLM、不改寫歷史事件，也不必等待下一次事件重算。

`frameworks.evidence` 保留事件 ID、標題、維度、LLM 正負強度與逐字原句。職場北極星頁需顯示有效證據數、已有證據的錨點數、最高指數，並以事件分組列出原句證據。事件明細不可顯示 `+8`、`-5` 等原始數值，以免被誤解為直接加減上方指數；改以「弱支持／中度支持／強支持／核心支持」與「弱反向／中度反向／強反向／明確排斥」呈現方向和強度。
